# Statement corpus

One record for each statement of the preprint, generated by
[build_corpus.py](../tools/build_corpus.py). This data is meant to serve a reader
later: it uses the [lean-exposition](https://github.com/wcook04/lean-exposition)
graph schema, and the statement text is the join key for everything else.

| File | Kind | Content |
| --- | --- | --- |
| `ties.json` | Reviewed | How each Lean declaration relates to a statement. |
| `receipts/` | Recorded | Results of actual builds and Comparator runs. |
| `lean_dependencies.json` | Recorded | The dependency closure read from the compiled environment. |
| `statements.json` | Generated | Statements, hashes and separate evidence fields. |
| `evidence-graph.json` | Generated | The same statements in the graph schema. |
| `coverage.json` | Generated | A count for each evidence field. |

The evidence fields answer separate questions, and none of them implies another:

| Field | Question |
| --- | --- |
| `formal_statement` | Does a Lean statement say this: `exact`, `stronger`, `partial`, `weaker`, or `none`? |
| `build` | Is the declaration in the compiled environment at the recorded commit? |
| `comparator` | Did Comparator accept it against an independent challenge? |
| `conditional` | Does the checked theorem carry an open hypothesis? |
| `route` | Does the Lean proof follow the preprint's, take an `alternative` route, or neither? |
| `reach` | Does the headline's proof depend on it? |

A Lean doc comment reading `Ledger: <id>` only proposes a tie. A statement counts as
checked through a reviewed relation and a receipt naming the declaration. See
[the contract](../docs/statement_evidence_contract.md).
